## 一、这个项目是干什么的

**一句话**：一个**零成本、全自动的中文每日资讯网站**——云端定时跑脚本抓新闻，DeepSeek 改写成"人话版"简报，自动发布上网，任何人免登录就能看。

```
GitHub Actions 定时（北京时间 08:00 / 18:00，共 5 个触发点）
   ↓ 运行 scripts/generate.js
① 抓 14 个中文新闻源（知乎/新浪 7 个频道/36氪/IT之家/极客公园/爱范儿/虎嗅/少数派/澎湃）
② 只保留"当天发布"的新闻，去重、打乱、截取前 60 条
③ 调 DeepSeek 大模型 → 生成 8 板块口语化简报（每条 = 换个说法的标题 + "发生了什么…看点：…"两句话）
④ 抓自选股实时行情（腾讯行情接口）+ 基金静态数据
⑤ 写入 site/data/ 静态 JSON（最新一期 + 当日归档 + 版次索引 + 日期索引 + 行情历史）
⑥ git 自动提交 → GitHub Pages 自动部署
   ↓
https://yihong-ally.github.io/daily-digest/   （另有 PushPlus 微信推送）
```

**八个板块**：今日必读 / AI·大模型动态 / 科技硬核 / 财经·市场 / 宏观经济 / 教育 / 互联网大厂 / 生活·消费

**网站功能**：按日期回看（57 天档案）、晨报/晚报版次切换、"长期关注"卡片（股票基金当前值 + 走势曲线 sparkline）、可点回原文链接。

**成本与依赖**：0 元（GitHub 免费额度）；无服务器、无数据库、无 npm 依赖；本机可关机。

| 代码仓库 | https://github.com/yihong-ally/daily-digest（默认分支 `main`） |

## 三、当前线上配置（以远端 `main` 为准）

**`.github/workflows/daily.yml`**：每天 5 个触发点（UTC）

| cron (UTC) | 北京时间 | 作用 |
|---|---|---|
| `0 0 * * *` | 08:00 | 晨报主触发 |
| `5 0 * * *` | 08:05 | 晨报补跑（已生成则自动跳过） |
| `0 10 * * *` | 18:00 | 晚报主触发 |
| `5 10 * * *` | 18:05 | 晚报补跑（已生成则自动跳过） |
| `0 14 * * *` | 22:00 | 兜底：检查当天缺哪期补哪期 |

job 流水线：`generate`（跑脚本 → `git add site/data` → 有变化才提交 → 上传 Pages 产物）→ `deploy`（`actions/deploy-pages@v4`）。

**脚本行为要点**（`scripts/generate.js`，490 行，零依赖）：

- 时段判定：`当前北京时间小时 < 14 → 晨报(08)`，否则 `晚报(18)`
- 已存在则跳过：`digest-YYYY-MM-DD-HH.json` 存在且未设 `FORCE=1` → 直接退出（补跑靠这个去重）
- 兜底模式：`MODE=topup` 时检查**当天** 08/18 两期，缺哪期补哪期
- 微信推送：`PUSHPLUS_TOKEN` 存在时，推送各板块前 2 条 + 行情快照 + 站点链接

### P1 ⚠️ 定时漂移 → 晚报系统性缺失 + 晨报提前到凌晨（影响内容完整性）

> 迁移初期另有 2 个晨报缺失（8-25、8-28）和 1 个晚报缺失（8-27），属 2.0 上线过渡期问题。

**机制（推断，逻辑可从代码直接验证）**：

1. Actions 的 `schedule` 实际触发时间比 cron 晚数小时（实测最晚晚 9 小时，例如北京时间 18:00 的晚报任务落到次日 00:48 才跑）。
2. 脚本用**跑的那一刻的钟点**判断版次：跨过午夜后 `hour = 0 < 14` → 被判定成"晨报"，日期也变成**第二天**。
3. 结果：本该产出的**前一天晚报永久缺失**，同时**第二天的晨报被提前到凌晨发**（内容里仍是当时的新闻，但档案上少了晚报）。
4. 22:00 的兜底任务同样被延迟到次日凌晨（如 10-19 的兜底到 10-20 03:38 才跑），此时它检查的是"新的一天"，看到 08 期已存在就认为无事可做，**补不回昨天的晚报**。

**这类缺失无法事后补**：脚本只保留"当天发布"的新闻（`pubDate === 今天` 才保留），历史日期重新跑也抓不回那天的新闻。

**修复方向（三选一，从轻到彻底）**：

| 方案 | 做法 | 改动量 | 可靠性 |
|---|---|---|---|
| A. 最小改动 | 脚本判定加保护：若 `hour < 6` 且前一天的 18 期缺失 → 按"前一天晚报"生成（日期回退） | 改 `run()` 里 5 行左右 | 高（沿用现结构） |
| B. 推荐 | 5 个 cron 拆成不同入参（`MODE=08` / `MODE=18` / `MODE=topup`），**版次由触发意图决定，不再看时钟**；topup 改为扫描"昨天+今天" | 改 workflow + 脚本入口 | 最高（延迟多久都不写错版次） |
| C. 兜底增强 | 每次运行先扫描最近 3 天，缺哪个版次补哪个；topup 覆盖昨天 | 改脚本 | 高（能自愈，但依赖素材仍在）

## 七、结论

项目**主体健康**：网站能开、内容每天在更新、台账结构完整、成本确实为 0，作为"每天两期中文前沿简报"的自动化流水线是**跑通并稳定运转的**。

真正需要动手的只有两件事：

1. **修时段判定**（否则晚报会继续随机缺失，且历史缺口补不回来）——这是唯一影响读者体验的实质问题；
2. **本地副本对齐线上**（否则任何一次"改完上传"都可能把兜底配置退回旧版）。

其余（行情误导、板块偏薄、废弃目录、临时垃圾、文档过期）属于打磨项，可以按上表顺序慢慢做。
